## 操作与布局

历史/动作/变量面板，文件 → 自动处理；用户选择输入文件字节、设置步骤和结果交付方式后在前台运行。四个面板同时挂在共享高级区域与菜单：历史记录/动作/变量与数据集在「窗口」（显示开关之后、文档清单之前），自动处理在「文件」。

复用固定上游 0.9.0 的生产算法，不修改 vendor。`rust/crates/editor-core` 持有规范内容、命令、预览草稿、身份与历史；`packages/protocol` 持有纯数据和限额契约；`packages/editor` 持有共享工具/面板。`dev` 与 `integrations/woohaa` 只装配公共端口，核心不得 import Woohaa 私有实现或内部工具。

界面沿用既有菜单 → 工具组 → 参数栏 → 原图/属性反馈的结构，菜单和参数栏在文档标签之上。所有状态均需有可见忙碌、失败与恢复反馈；面板仍使用现有浮动/停靠能力，不重新设计外壳。只验收电脑 1440×1000 和 Pad 正常窗口 1024×768；手机/极窄窗口和无障碍专项不在范围。

## 本域实现决策

### D1

命名快照固定真实规范内容及相关资源，属于会话历史而非自动嵌入工程；清理前显示具体范围并确认，清理不改当前像素/保存基线。历史画笔消费者使用稳定有界源句柄（`historyState().epoch` = 文档身份 + 状态标签 + 重做标签；`sources[].live` 标记唯一活文档）。

实施补充（本 change 落地时确认）：`epoch` 只说明「哪一份历史源」，本身不会阻止消费方按旧索引取样。因此本域另给一个**取样读取点** `history.sample`（wasm `sampleHistory`）：调用方必须带上取源时的 `epoch`，与当前摘要不一致即拒绝并明确「不会按旧索引返回新内容」；归档状态取 `history.state(i)`、活状态才用当前文档，返回 RGBA8 预览 + 尺寸 + `live`；同一入口的 `preview: false` 只校验句柄、不合成像素，供历史画笔落笔前廉价判定。它是读取点而非命令：**不进** `HISTORY_COMMANDS`、不注册 capability（`features:check` 的命令/能力基线因此不受影响）。清理范围说明同样带 `available`/`reason`，并且 `bytes` 必须等于实际释放量（`videoCache` 恒为 0，`undo` 只算一步的差额，`all` 除历史外还要累加剪贴板与渲染缓存），否则「清理能省多少」会比没有更误导。

实施补充（本 change 落地时确认）：「自历史新建」在早期计划里写的是「经工作区注册」，实际实现时发现内核 `history.newDocument` 会把**活动文档**切到新文档，而宿主标签仍指向源文档——留在这个状态会让下一次保存把派生内容写回源节点。因此当前实现是**取走派生工程字节后立即关闭内核派生文档**，把派生工程作为 `.pcraft` 文件交付，当前文档（hash/修订/标签/保存目标）完全不受影响。要让派生文档成为工作区里的**活动标签**，还需要 `document.activate`（当前 capability 禁用）与「未命名文档的保存目标」两条产品语义，属外部产品决策，未在本 change 内决定。

### D1a

`doc.variables`（变量 + 数据集）是本域唯一会持久化的内容，因此必须进共享内容身份与工程核验，否则「只改变量/数据集」不改变指纹，脏标记与保存基线会一起失效。规范形式是一条尾随 `variables:[…][…]` 行，字段按 UTF-16 长度前缀；**空变量省略该行**，保证旧工程指纹逐字节不变。定义与数据集**顺序敏感**（`image.variables.define` / `image.variables.dataSets` 都是整份替换）；`active` 指针属配置而非内容，不进身份——但它不进身份**不等于**可以留错：上游只存下标，整份替换后下标不变、含义却会变（`[A,B,C]` 生效 B，删 A 后仍指 1 → C），因此域层在替换后按**名称**重定位，生效项被删则清空。工程核验用**文档级**钩子（`DOCUMENT_INSPECTORS`），因为 `INSPECTORS` 是逐图层的，表达不了 `doc.variables`。

### D1b

12 个能力 id 随已交付阶段 `P7` 发布，发布前四项前置必须同时成立：命令进唯一命令门、真实 WASM 主线、React 入口、内容身份与文档级核验。缺任何一项就只登记命令、不发布能力——本 change 是在补齐 D1a 之后才发布的。

### D2

动作只录制成功提交的规范命令及参数/必要资源，不录指针事件、临时 preview 或 Woohaa 私有操作。播放先解析能力和目标映射，一步一个现有命令事务；失败停在明确步骤，保留已成功结果并允许撤销，不宣称整组原子。ATN 按可解释子集预检，未知步骤默认拒绝整组导入，显式选择可支持子集才发布。

### D3

自动化使用前台、用户发起、可取消的有界队列；输入/输出经 files 的字节/交付端口，逐文件候选文档完成后交付，失败保留逐项报告。数据集绑定文本/像素/显隐层稳定 id，CSV/资源一并预检；脚本仅可声明式调用已允许命令，不 eval 任意 JS/Rust 或启动原生进程。

### D4

U76 中 Batch/Image Processor/Contact Sheet/Load Stack/变量数据集交付浏览器流程；原生 Droplet 可执行程序、任意脚本事件及磁盘监控明确暂缓。脚本事件若支持，仅工作区生命周期的受限动作绑定，禁止循环触发。

## 事务和生命周期

内容操作遵守 begin → preview → commit/cancel：固定 documentId/generation、baseRevision、目标及 attemptId；预览不变正式内容 hash/修订/历史，确认最新有效候选一次，取消恢复，无变化不新增历史。非法参数不得确认上一份成功预览。一次笔迹/拖动按既有完成规则提交，不强制所有参数都变成弹窗。

保存、切文档、关闭、只读变化和父子回写复用活动草稿门禁。晚到任务按文档代际和请求序号丢弃，不能写入后来活动文档。只读采样和工具/查看偏好不制造文档 dirty。分组队列若有不同语义必须在具体设计中声明，不虚构跨文档原子事务。

## 内容、协议与核验

逐能力同步参数解码、唯一命令门、WASM、React、内容身份、工程序列化、TS 检查和原生核验器；实际接通后才发布能力，不把整个命令前缀放开。共享限制只在 `rust/project-limits.json` 与两端 fixture 中维护；不整体提升现有 8192 单边、64 图层、64 MiB 工程、16 嵌套深度和 8 文档上限。

新增规范内容缺省/空值保持旧工程身份兼容，工具本机设置/视图不进入内容 hash。涉及新持久字段时必须给出与旧运行时的能力协商、解码前累计预算和资源引用验证；未知内容不能通过通用 JSON/PSD 原始块绕过。PSD 与 LayerTransferBundle 的兼容项逐类型更新，无法表达时报告而非静默压平。

## 取舍与发布条件

优先复用上游算法和现有 UI/草稿，避免复制另一套内容状态。不能编译进 WASM、没有 codec/字体/硬件或缺公共端口的子能力单独记录停止原因，不能因此把整个域标为完成。

MCP、后台批处理、任意脚本执行、原生 Droplet/进程/路径和打印仍为排除或平台暂缓，不从 NON_GOALS 一次移除。

## 验收主线

命名快照 → 自历史新建 → 录制两步动作 → ATN 往返/未知步骤报告 → 两个文件前台批处理 → 数据集替换；中途取消不继续交付。 具体成功/失败情景和逐项证据见 specs 与 verification；实际像素、结构、历史和工程往返都通过后才开放相应子能力。

## 实施中的语义修正（记录以对齐实现与计划）

以下上游语义与计划写法不一致，实现按上游的真实语义处理，并在回归里固定；没有为了贴合计划而改内核行为：

- `history.deleteState` 是**先退回该状态之前再清空其后所有状态**（内容回退且不可重做），不是「删一行记录」，因此面板先说明后果再确认。
- `actions.play` 中途某步失败时**仍返回成功**，失败放在 `{failed:{step,id,error}}`。域会话必须读 `failed` 并如实报错。
- `actions.conditional` 的 `journal` 为 `true`——它会**播放命中的分支**并写内容，因此走草稿门禁 + `afterWrite`，不是只读工具。
- `edit.purge.histories` 只清撤销状态，**保留**命名快照；「清理后快照消失」是错误预期。
- `image.variables.define` 是**整份替换**，像素变量的 `method`/`align`/`clip` 展平在 def 上；重发时必须原样带回。
- `batch.finish`（收尾）会连未领取的交付字节一起丢掉，因此有未领取项时先说明并确认。
- `history.newDocument` 会切走活动文档——见 D1 与 D1a 的实施补充说明。
- `actions.save` 默认**拒绝**含非 Photoshop 等价步骤的动作（只提示传 `skipUnsupported`，不会自行省略）；
  跳过导出必须由用户显式选择，且内核返回的 `skipped` 要逐条显示，不能只说「导出成功」。
- 「文件」菜单在宿主没有注入任何文档动作时也要由域入口独立成立：否则只注入 `documents.transfer`
  的独立 dev 宿主里 `menu: "文件"` 的「自动处理…」完全没有入口，面板只能靠「高级…」猜到。
- `history.sample` 是**读取点**，不是命令：它不登记进命令门，也不发布 capability。它的身份校验
  只接受取源时的 `epoch`，拒绝时说明「取源时为 X，当前为 Y」；缺 `epoch` 一律拒绝（没有身份
  就无法判定失效，不能默认当前状态）。同一个读取点带 `preview: false` 时只做**同一套**校验而不
  合成像素——历史画笔落笔前每次都要问「源还能用吗」，若只能走缩略图路径就会每笔分配一次 RGBA
  缓冲。两条路径的拒绝条件必须逐字一致，否则「检查说可用、落笔却被拒」。
- 面板在清理后**刻意保留**取源 `epoch`：这样下一次取样会如实报失效；换源必须显式点「重新取源」，
  否则一次清理就会把取样悄悄改绑到新状态，用户以为看的还是原来那份归档。
- 取样的像素必须**看得见**：面板把 RGBA8 画到 canvas 并在绘制前核对 `width × height × 4`，
  长度不符报错而不是画半张图。只显示「128×128」等于把端口返回的结果丢掉，用户无法分辨取到的
  是归档那一刻还是当前画面。
- `edit.purge.all` 的范围说明不能与 `histories` 共用求和：`all` 还释放剪贴板与渲染缓存
  （效果图 / 合并蒙版 / 智能滤镜阶段），必须累加。形状描边缓存没有公开字节读数且探测会清空它，
  因此 `all` 是「已可测部分之和」——只会低报不会高报，内核用 `approximate: true` 标出来，界面
  据此说「约」，其余范围说「正好」。可用但 `bytes` 为 0 也不等于「当前为空」：共用 tile 的状态清掉后
  腾不出空间，却仍会丢掉整个撤销栈，界面必须这么说。
