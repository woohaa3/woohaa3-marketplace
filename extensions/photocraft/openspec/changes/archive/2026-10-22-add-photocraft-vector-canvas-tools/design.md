# 形状与路径画布工具设计

## 基线与范围

固定上游 commit `4e7a17cd5d5723313f459753663d0d155f047e19`；已提交实现 `bdc3c0847fa7d2ed5db82128dafcf3f47ad1bfa1`。范围逐项列于 [scope.md](scope.md)，每个 U 组的子能力都需拆成实现时的命令/参数/操作记录，不以一组一个按钮结案。

同级前置：无新增同级 change 的硬依赖。相邻模块只是消费端口的软依赖时，以现有内核能力完成基础流程，新增联动在两边均交付后验证。原 change 的未验收项仍按其证据处理；本计划仅追加缺口，不自动勾选或重写旧任务。

## 操作与布局

左侧形状/钢笔工具组 → 顶部填充、描边和几何参数 → 图内拖绘/选点；属性面板显示当前选中形状，不另建一套独立画布。

复用固定上游 0.9.0 的生产算法，不修改 vendor。`rust/crates/editor-core` 持有规范内容、命令、预览草稿、身份与历史；`packages/protocol` 持有纯数据和限额契约；`packages/editor` 持有共享工具/面板。`dev` 与 `integrations/woohaa` 只装配公共端口，核心不得 import Woohaa 私有实现或内部工具。

界面沿用既有菜单 → 工具组 → 参数栏 → 原图/属性反馈的结构，菜单和参数栏在文档标签之上。所有状态均需有可见忙碌、失败与恢复反馈；面板仍使用现有浮动/停靠能力，不重新设计外壳。只验收电脑 1440×1000 和 Pad 正常窗口 1024×768；手机/极窄窗口和无障碍专项不在范围。

## 本域实现决策

### D1

第一里程碑先交付矩形、椭圆、直线的完整画布手势，再扩形状、节点和布尔运算。保留已有数值创建入口，图内与数值使用同一候选几何；Shift 约束比例/角度，Alt 从中心，单击打开尺寸输入。

### D2

以源像素坐标保存锚点、入/出控制柄、子路径与 closed 状态。前端仅绘制命中和操控叠加层，贝塞尔求值、填充规则、布尔运算和变换边界由 Rust/上游负责。开放路径不强行闭合；自由/曲率钢笔转换为同一规范路径。

### D3

形状拖绘或一次节点拖动采用隔离草稿，松手提交一步；多点钢笔以显式完成/双击/闭合结束，Escape 丢弃尚未完成路径。路径与蒙版引用统一 remap，形状库删除不删除已经应用的几何快照。

### D4

路径命令按具体参数开放，补齐现有 composition 几何验证、内容身份、工程核验及跨文档/PSD 矩阵；无法在 PSD 表达的形状默认报告，用户可另导栅格副本。

实施补充（3.2）：已存命名路径 / 工作路径 / 裁切引用**确实进入 `contentHash`**，
以顶层可选字段折叠成规范后缀行（`paths:[…]` / `work:` / `clip:`），空值整体省略，
因此没有路径的旧工程指纹逐字节不变。这项决策的代价是多改两处冻结文件
（`contract.json` 与 `project-limits.json` 只新增键），已验证 8 组状态/内容快照与
`bdc3c084` 逐字相同。

实施补充（3.2 续）：同一判据也适用于**形状外观**与**蒙版外观**——`shape.fill` /
`shape.stroke`（全部字段）/ `LiveShape` 规范参数、矢量蒙版的 `density`/`feather` 都在
`.pcraft` 里逐字段保存，因此以**图层内可选后缀**参与身份（`shape:<几何>[:appearance:<摘要>]`、
`|vector:…[:density:…][:feather:…]`），而不是顶层行——这样没有矢量内容的工程连后缀都不出现。
选择「只补持久字段、不改视图/工具状态」的边界不变：预设库、面板选择、参考线都不进指纹。

### D5 晚到写入用文档代际令牌，不用请求序号

本节开头「晚到任务按文档代际和**请求序号**丢弃」是通用原则。本域的实际情况是：
矢量命令全部**同步**执行（一次手势产生的命令数组按序调用、首个失败即停止），
不存在可乱序返回的异步队列，因此没有序号可编。落地方式是：

- 手势开始时取 `VectorDocumentToken = { generation, session }`，每条命令回传；
- 代际或活动文档索引不符即返回 `code:"stale"`，**内核不被调用**，绝不写入后来活动文档；
- 一次手势内的顺序由「按数组顺序同步执行」保证，而不是序号比较。

需要真正异步序号的场景（直方图等）继续用既有的 `generation` 回传机制，本域不复用它。

## 事务和生命周期

内容操作遵守 begin → preview → commit/cancel：固定 documentId/generation、baseRevision、目标及 attemptId；预览不变正式内容 hash/修订/历史，确认最新有效候选一次，取消恢复，无变化不新增历史。非法参数不得确认上一份成功预览。一次笔迹/拖动按既有完成规则提交，不强制所有参数都变成弹窗。

保存、切文档、关闭、只读变化和父子回写复用活动草稿门禁。晚到任务按文档代际和请求序号丢弃，不能写入后来活动文档。只读采样和工具/查看偏好不制造文档 dirty。分组队列若有不同语义必须在具体设计中声明，不虚构跨文档原子事务。

## 内容、协议与核验

逐能力同步参数解码、唯一命令门、WASM、React、内容身份、工程序列化、TS 检查和原生核验器；实际接通后才发布能力，不把整个命令前缀放开。共享限制只在 `rust/project-limits.json` 与两端 fixture 中维护；不整体提升现有 8192 单边、64 图层、64 MiB 工程、16 嵌套深度和 8 文档上限。

新增规范内容缺省/空值保持旧工程身份兼容，工具本机设置/视图不进入内容 hash。涉及新持久字段时必须给出与旧运行时的能力协商、解码前累计预算和资源引用验证；未知内容不能通过通用 JSON/PSD 原始块绕过。PSD 与 LayerTransferBundle 的兼容项逐类型更新，无法表达时报告而非静默压平。

## 取舍与发布条件

优先复用上游算法和现有 UI/草稿，避免复制另一套内容状态。不能编译进 WASM、没有 codec/字体/硬件或缺公共端口的子能力单独记录停止原因，不能因此把整个域标为完成。

路径文字、竖排文字以及未实现的菜单目录项保持排除；不以 SVG 叠加画面代替可保存几何。

## 验收主线

U 工具画矩形并改圆角/描边 → 建开放贝塞尔 → 调手柄/布尔组合 → 作为蒙版 → 保存重开和跨文档复制。 具体成功/失败情景和逐项证据见 specs 与 verification；实际像素、结构、历史和工程往返都通过后才开放相应子能力。
