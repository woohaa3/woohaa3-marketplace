# 共享 Web UI 编辑能力设计

## 目标与界面方向

面向在电脑和 Pad 上合成、修图及绘画的用户，沿用现有编辑器的工具栏、工具参数栏、图层／属性面板与原图预览。用户应能完成“选笔修蒙版 → 跨文档组合 → 可编辑 PSD 往返 → 编辑智能对象内容 → 调色和修饰”的连续任务。成功证据是实际像素、结构、历史和工程往返，不是新增菜单数量。

本 change 是一个分阶段交付的编辑能力集合，完成 P1 不等于整个 change 完成。各阶段只开放已接通并通过该阶段验证的能力；禁止一次解除整个 disabled 清单。无独立产品外壳和视觉重设计。

## D1 代码边界和公共工作区

- `packages/protocol` 负责纯数据契约、能力版本、参数解码、载荷摘要与限制；不依赖 DOM 或宿主。
- `rust/crates/editor-core` 负责命令、采样算法调用、草稿、合成、身份及历史；`wasm.rs` 只转换类型。上游算法经本地包装复用，不修改 vendor。
- `packages/editor` 负责共享 React UI、工具状态、文档注册表及公共工作区协调器。新增跨文档和子文档行为不得藏在 Woohaa 插件里。
- 宿主提供字节读取、文件交付、Dialog、取景与预览端口。核心的文档身份是 opaque id + generation，新增接口不要求 canvasId/nodeId；节点身份由适配层映射。
- `dev/` 增加最小 A/B 文档与子文档装配以验证共享实现；不新增最近文件、账户或发布壳。Woohaa 复用既有 Tab、节点预览与文件工作区，只有活动文档持有输入／预览。
- 跨文档、子文档关联等服务归工作区持有，按工作区释放；禁止全局可变剪贴板串到别的工作区。

## D2 分阶段能力发布

| 阶段 | 可交付行为 | 依赖与停止条件 |
| --- | --- | --- |
| P0 | 能力／命令／格式／资源矩阵、fixture、公共协调端口 | 每项须核对上游源码及实际 WASM 可用性；不能仅引用 egui 文档 |
| P1a | 预设、笔尖、压感和平滑，真实圆形笔刷手感 | 鼠标回归和真笔验证分别记录；未测不宣称手感达标 |
| P1b | ABR、采样笔尖、纹理散布与动态 | 解析、资源预算、笔迹一致性及持久化通过后开放 |
| P2 | 跨文档图层／组与图片像素置入 | 原子导入、资源身份迁移、源关闭后可粘贴 |
| P3 | RGB/U8 PSD 导入导出 | 先交付兼容矩阵；P4/P5/P7 未完成的类型明确报告为不支持 |
| P4 | 嵌入智能对象及子文档回写 | 扩展 P2/P3 的类型矩阵并核对嵌套身份与核验器 |
| P5 | 新调整层、直方图、像素选区与边缘细化 | 草稿原子性、蒙版及 PSD 映射分别验收 |
| P6 | 修饰笔迹和两种参数滤镜 | 不支持的目标／采样组合在落笔前拒绝 |
| P7 | 构图辅助、文字排版和矢量 | 扩展 PSD／剪贴板矩阵，完成跨宿主综合验证 |

P0、P1a 优先；P2 → P3 → P4 顺序实施，P5/P6/P7 可在前置契约稳定后逐项推进。每阶段的声明、入口和实际运行时必须一致；不能靠隐藏图标保留可绕过的命令。

## D3 所有编辑沿用同一事务规则

内容写入使用 begin → preview → commit/cancel；开始时冻结文档 id、generation、baseRevision、内容 hash 及目标。临时预览不推进正式修订、指纹、撤销／重做或保存基线。确认仅提交一次；无变化不增加历史，非法参数不得确认上一份有效预览。取消、pointercancel、释放、只读切换按现有草稿政策恢复。

长任务使用 attemptId 与文档代际，取消或过期结果直接丢弃。切换、关闭、保存和父子回写必须先经过活动草稿／笔迹门禁。预览结果只能发布到对应活动呈现；后台子文档仍能保留内容与历史。新增入口均尊重文字输入和 IME，不让工具快捷键截获输入。

已有自动提交型属性手势继续采用其既有确认规则；本设计不把每个滑杆强制变成弹窗。新操作在参数栏／面板就地展示忙碌、失败、重试和取消，不引入另一套通知壳。

## D4 笔刷

工具参数栏保留大小、不透明度、流量等高频参数；预设选择器显示名称、笔尖缩略图和笔迹预览，独立“笔刷设置”面板容纳笔尖、形状动态、散布、纹理、颜色动态、传递及平滑。按开关启用参数，禁用保留用户值。预览使用真实内核和固定 seed／压力轨迹，不用 CSS 画近似笔迹。

P1a 开放间距、角度、圆度、翻转，以及大小／不透明度／流量的压力控制、最小值和全局压力曲线。鼠标压力使用明确的恒定值；pen 输入保留每个 coalesced sample 的 pressure，支持 tilt 的平台另传 tilt，缺失数据回退为无倾斜，不能伪造。平滑优先支持量、拉绳和追赶语义；源坐标计算与显示缩放分离。修改笔刷偏好不改变文档；一笔冻结所用设置，整笔一个历史步骤。

P1b 复用上游 ABR v1/v2/v6 解析基础，接入可核验的采样笔尖与动态子集；本地 PNG 灰度／透明度可定义静态笔尖。未支持的 ABR 设置须逐笔报告，不能无提示变成普通圆笔。默认整批拒绝不支持记录；用户明确选择“仅导入可支持笔刷”后才发布子集，并保留报告。

库使用独立的版本化存储适配，支持保存／覆盖／重命名／删除／分组和重载。持久化失败保留内存并提示，不宣称已保存；导入资源成功前不发布半个库。工具预设与文档分离，画笔／橡皮分别保留设置；笔迹已落为像素后工程不依赖用户笔刷库。纹理笔刷引用的笔刷资源进入库预算，不混入无关文档资源。

初始 ABR／笔刷预算：单文件 32 MiB、单次导入／库总数 256、单笔尖边长 1024、库内采样笔尖和纹理累计 16,777,216 像素、解码累计 128 MiB。P0 将这些数据写入 `rust/project-limits.json` 并同步 TS/Rust fixture，不散落魔数。程序性硬圆／软圆和若干静态采样笔尖作为首批默认预设，不引入来源不明的画笔资产。

## D5 跨文档复制与素材置入

新增版本化、自包含且有界的 `LayerTransferBundle`：包含规范层树、蒙版／样式、文字／调整参数、图案及后续嵌入源等所有引用、源文档尺寸、布局锚点和摘要。Rust 导出与导入，JS 不拼写层结构；载荷不含活的内核指针、Woohaa 节点、远端 URL 或系统剪贴板权限。

复制不修改源文档；源关闭后已复制的载荷仍有效。粘贴先解码、核验、重映射图层／资源／嵌入源身份，再以目标候选文档提交一步。等价资源按内容复用，冲突 id 重映射且改写全部引用；不覆盖目标同 id 资源。保留层组顺序、锁定／混合、蒙版和已有变换。原位粘贴使用源文档像素坐标，普通粘贴以目标可见中心放置整个集合。默认跨文档复制独立化智能对象源，同一载荷内部的共享关系保留。

图片置入通过 `EditorImportPort` 一类结构端口取得名称、MIME 和 bytes，然后走内核预检；先交付像素层置入，P4 开放嵌入智能对象。拖放只传字节，不把“打开独立文档”和“置入当前层”混为一个动作。跨文档剪切不做两个文档的分布式事务：本次跨文档只提供复制／粘贴；已有文档内剪切保持原语义。

## D6 PSD：支持矩阵优先于开放扩展名

首期只接受 PSD v1、RGB/U8，继续受 8192 单边、64 图层、64 MiB 工程及既有解压／条目／深度上限约束。PSD 原始输入和单次交换载荷各限 64 MiB；候选工程仍须满足保存预算。PSB、其他色彩／位深在分配像素前拒绝。

P3 兼容矩阵逐特性列出：导入可编辑、导出可编辑、合成保真 fixture、损失／拒绝原因。像素、普通组、像素蒙版、混合／填充不透明度、已接文字／调整／样式逐个验证，不能笼统标记“支持 PSD”。P4/P5/P7 再加入智能对象、新调整、形状与矢量蒙版；只有通过双向 fixture 的项进入可编辑矩阵。

解析和映射先在候选文档进行；截断、超限或不支持的可编辑内容默认拒绝。若源有合法合成图，可明确选择“作为扁平副本打开”，报告会丢失哪些编辑结构，不污染原文件或当前文档。导出先生成逐图层报告；默认保留可编辑结构，无法表示时拒绝，用户可明确选择对列出的内容栅格化后导出副本。未知 PSD 原始块不作为可编辑工程后门保存；不能保证的效果明确报告。

PSD 导出为文件交付，不取代 `.pcraft` 原生保存，不自动清除工程未保存状态。必须在真实 Photoshop 中核对一组导入／再编辑／导出结果；只通过本引擎自导自读不能证明 Photoshop 兼容。

## D7 嵌入智能对象和子文档

复用已有 `smart_convert`、`smart_copy`、`smart_source_edit`、`smart_source_render`、`smart_identity`。P0 先核对其真实能力与核验器状态，不重新实现另一套源关系。

实例 layerId 与 contentsId 分离：普通复制共享父文档内的 contentsId；“通过拷贝新建”独立化；跨文档默认独立化。转换所选层／组为嵌入对象提交一步，保留视觉布局；替换内容保留实例变换和适用样式。选择像素工具时提示先编辑内容或显式栅格化，禁止悄悄改写对象缓存。

“编辑内容”建立 parentDocumentId/generation、contentsId、sourceHash 和父基线的关联，打开一个真实子文档；同一父源复用已开的子文档。子文档在通用工作区占用一个文档名额，8 文档预算包含子文档，嵌套不绕过 16 深度及累计资源预算。

子文档的“更新父文档”与本地“导出工程”明确区分。回写前核验父关联、源基线和现有事务的 baseRevision；保守地将父内容修订变化视为冲突。回写准备完整候选父文档，重算所有共享该源的实例，提交一次父历史；失败无部分更新。父事务已提交而 UI 回执丢失时，同 attemptId 的重试返回原结果，不再提交第二步；登记回写结果及关联新基线须与父事务同一边界更新。

冲突不自动覆盖或按旧基线重放：保留子文档，提供重新载入父源（确认丢弃子修改）、另存子工程、在父文档建立独立对象副本等明确恢复路径。父关闭／删除对象／撤销源／只读变化使关联失效时，子文档成为可保留的独立文档，不丢弃修改。无变化回写不产生父历史。父子修改各自保持 dirty，不因切 Tab 自动回写。

## D8 调整、选区、修饰和滤镜

新增色阶、R/G/B 通道曲线、自然饱和度和黑白均支持调整层与已有层重编，使用当前草稿协议；直方图可选当前层／可见合成和 RGB／亮度，按请求代际发布，只读不污染历史。需要采样的参数工具由内核读取源像素。

选区增加魔棒容差／连续／采样全部图层、快速选择和色彩范围；统一替换／加／减／相交。增加扩展、收缩、平滑、边界及“选择并遮住”的半径／羽化／对比度／边缘偏移与前景／背景手工修边。输出可选选区或像素蒙版，先预览后一次确认；不标记为 AI 发丝识别。选区变化依旧不改变文档内容 hash，输出蒙版才修改工程。

修饰复用笔刷采样、选区、锁定、压感和一步撤销：图章有明确采样点、对齐开关和来源模式；修复／污点修复明确采样来源；模糊／锐化／涂抹与减淡／加深／海绵有强度及适用参数。首批仿制／修复支持当前层和当前及以下可见合成采样，目标仅可写像素层；需要非破坏修饰时由用户选择空白像素层，不自动改智能对象或文字。采样以本笔开始的源快照为基线，避免递归采样正在写入的结果。

高斯模糊和 USM 锐化先作用于可写像素层及选区，弹层确认提交一步，关闭／取消恢复原内容，不宣称智能滤镜。当前目标不支持时在开始前说明原因。无法完成实时局部预览的上游命令不直接开放，要先补齐与正式结果一致的预览通路。

## D9 构图、文字和矢量

标尺、参考线、网格、吸附及图层搜索属于编辑器工作区控制，不增加内容 dirty／撤销；本次不要求参考线写入 `.pcraft` 或 PSD。取景与吸附统一使用源坐标，缩放改变屏幕阈值换算；候选吸附含文档边／中心、参考线、图层边／中心并显示对齐反馈，可临时关闭。图层过滤只影响列表，不改变选择、绘制或层树。

裁剪先显示可调整边界和尺寸／比例，确认更新文档及所有受影响的层、蒙版、路径、选区和智能对象实例变换，提交一步；先实现明确的“删除裁剪像素”模式，不承诺非破坏隐藏裁剪。图像尺寸有重采样选项，画布尺寸有锚点和新增区域背景；超限和失败不改变原文档。平移使用既有取景端口，不和移动图层混淆。

文字继续使用内核布局与真实输入节点，在已有水平点／段落文字上补行距、字距、字偶距策略和基线偏移；字体列表仅显示已注册字体及实际可用字重，缺字体可明确映射替换并报告，不伪造字体可用性。参数不支持时禁用并说明，不能只有 DOM 预览。路径文字、竖排和任意系统字体发现不在范围内。

矢量首批为钢笔直线／贝塞尔节点及控制柄编辑，矩形／圆角矩形／椭圆、填充／描边，以及路径转选区和矢量蒙版。矢量数据、蒙版关系和几何运算在内核，不由 SVG 叠加层成为第二份权威数据；叠加层只显示／编辑控制柄。与像素蒙版共存时采用内核规定的相乘覆盖，并进入合成、指纹和核验。复杂布尔路径、SVG 全量导入导出留待后续。

## D10 版本、指纹与资源

每阶段对实际支持的图层／参数／资源更新能力版本、稳定错误和 fixture；`.pcraft` 容器版本只有编码不兼容时才变更，不能仅改版本绕过核验。旧工程可读；缺失新字段使用兼容默认值，空新集合保持旧内容 hash。新增调整／矢量／嵌入源按规范内容进入 hash；笔刷偏好、库、标尺、参考线、直方图和图层搜索不进入内容 hash。

新增 PSD／ABR／载荷大小等限制与原工程限制共用 `rust/project-limits.json`，TS 和 Rust 分别读共享 fixture。现有核验器已支持的智能对象基础先复核，再补真实缺口；不将已完成的原生基础当成新实现。递归源、解压资源、图案和层数使用共享累计预算，不能每层重新领满额度。关闭文档释放源／笔迹／载荷临时资源；持有的工作区剪贴板按独立预算管理。

浏览器编辑核验、Node 结构核验、原生核验与运行时能力协商一起更新。新编辑器生成的合法工程不得被本机宿主当旧能力拒绝；旧运行时遇到不可编辑的新能力须明确拒绝或已有只读查看，不静默转 PNG 重建。

## D11 验收与回退

每个阶段分别验证独立 dev 和 Woohaa 适配，核心不 import 宿主，由同一 fixture 验证 TS/Rust 的输入、身份和失败语义。UI 使用真实工具操作，不仅调用 dispatch；覆盖取消、只读、超限、失效代际和保存重开。P3/P4/P7 在 Photoshop 做外部交换验证；P1/P6 在真实数位笔／GPU 环境测试手感、长笔、轻压和修饰结果。

按平台探测 GPU；无真实 GPU 的 CI 只做非渲染检查。未执行的图像、帧率或真笔验收保留为待人工验证并写真实原因，不用软件渲染替代。性能报告记录测试硬件、文档尺寸、笔尖和样本，未测不写绝对延迟承诺。

阶段失败可关闭该能力入口和命令，保留已有工程、草稿和旧格式读取；不得通过降级保存丢失新内容。能力清单同步回退，不单独回退 UI 或 WASM。实施时更新 README、PhotoCraft 模块地图和受影响宿主地图，地图只记录落地实现。

## Considered Options

- 直接移植上游 egui 全部菜单：其状态／渲染和 React 不同，且部分笔刷／修复手感仍有已知差距，不能作为完成依据。
- 新做独立 Web 应用并复制编辑器：违背共享核心方向，产生两套功能和修复；本次只扩展现有包。
- 把 PSD 或 ABR 接口解锁视为完整支持：无法说明编辑结构损失和参数缺口，采用预检、矩阵、fixture 和明确的转换副本。
- 把所有高级能力一次承诺：PSB／专业色彩、湿画／特殊笔刷、外链源、智能滤镜和 AI 抠图分别需要不同资源或算法工程，保留明确后续范围。
